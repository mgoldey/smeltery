# Bench Implementation Plan

> **Superseded (2026-11-03) by `ralph/bench/features.json`**, which the Ralph loop works from.
> Kept for its reasoning and its record of the first implementation pass. Do not work from this file.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Bench end to end: put the seams under test, close the gaps nothing has implemented, then the three areas and the ELN, so a computational chemist opens a structure, builds a pipeline by clicking, runs it, reads the verdict, decides, and hands a bench chemist a page they can answer.

**Architecture:** Ports-and-adapters (onion), dependency rule inward. `smeltery/bench/ports/` holds Protocols; `adapters/` implements them over SQLite and the filesystem; `use_cases/` orchestrates and speaks only to ports. One contract test suite per port runs against every adapter, so a new adapter is correct exactly when it passes. The existing toolkit-free core (`funnel`, `gui.results`, `gui.pipeline`, `decisions`, `study`) is reused unchanged.

**Tech Stack:** Python 3.11-3.12, pytest, FastAPI + Starlette `TestClient`, SQLite (stdlib `sqlite3`), pydantic 2.14, RDKit, `ty` 0.0.96 via `uvx`, ruff.

**Spec:** `docs/superpowers/specs/2026-11-03-bench-gui-design.md`

## Review Focus

Input classes the spec implies but no task's own happy path exercises, most likely to bite first. Each has a test in the task that owns the code.

1. **A `run-*.json` that is not a run record** (truncated, hand-edited, wrong schema) reaches `RunStore.list_runs`. Expected: that run becomes a row carrying `error`, the other runs still list, nothing raises. Task 3.
2. **A record with no `results.cut`** — a run whose task died mid-SCF — reaches the Run surface. Expected: INCOMPLETE rendered as itself, never a blank where a verdict belongs. Tasks 7 and 9.
3. **A task id that does not exist** reaches `TaskQueue.get`/`status`/`cancel`/`tail_log`. Expected: `get` returns `None`; `tail_log` raises `KeyError`; `cancel` is False or `KeyError`, consistently across both adapters. Task 5.
4. **Temporal unreachable** when the dashboard asks for tasks. Expected: 503 carrying the reason within ~2 s (not a hang), while `/api/runs` still answers 200. Task 7.
5. **A pipeline whose `path` knobs point outside OUT** at launch. Expected: inputs staged into OUT by hash and knobs rewritten, so the archived config resolves inside OUT. Task 10.
